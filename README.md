# Weblog Project

A server-side weblog application built with **Node.js, Express, MongoDB, Mongoose, and EJS**.

The project follows a modular MVC-style structure and includes blog management, user authentication, an administration/dashboard area, sessions, file uploads, logging, email utilities, and database persistence.

## Features

- Blog post management
- User authentication and login
- Admin/dashboard area
- MongoDB database integration
- Mongoose models
- Session-based authentication
- Passport.js authentication
- Password hashing with `bcryptjs`
- reCAPTCHA support
- Flash messages
- File uploads
- EJS server-side rendering
- Express layouts
- Email functionality with Nodemailer
- Request logging with Morgan and Winston
- Environment variable configuration
- Custom error / 404 handling
- Jalali date support

## Architecture

The project is organized into several major directories:

```text
weblog-project/
├── config/
├── controllers/
├── logs/
├── middlewares/
├── models/
├── public/
├── routes/
├── utils/
├── views/
├── app.js
├── package.json
└── package-lock.json
```

### `config/`

Contains application configuration such as:

- Database configuration
- Passport configuration
- Logging configuration
- Environment configuration

### `controllers/`

Contains the application's business logic.

Current controllers include:

```text
controllers/
├── adminController.js
├── blogController.js
├── errorController.js
└── userController.js
```

The controllers handle operations related to users, blogs, administration, and errors.

### `models/`

Contains Mongoose models:

```text
models/
├── Blog.js
├── User.js
└── secure/
```

`Blog.js` represents blog data and `User.js` represents application users.

### `routes/`

Defines the application's HTTP routes.

The main application mounts:

```text
/              → blog routes
/users         → user routes
/dashboard     → dashboard routes
```

### `middlewares/`

Contains reusable Express middleware, such as authentication and access-control logic.

### `views/`

Contains EJS templates used to render the application's HTML pages.

### `public/`

Contains static frontend assets such as CSS, JavaScript, images, and other public files.

### `utils/`

Contains reusable helper functionality, including utilities such as mail handling.

### `logs/`

Contains application log files generated by the logging system.

# Application Flow

The main entry point is `app.js`.

The application:

1. Loads environment variables.
2. Connects to MongoDB.
3. Configures Passport.
4. Creates the Express application.
5. Configures logging.
6. Configures EJS as the view engine.
7. Enables URL-encoded and JSON request bodies.
8. Enables file uploads.
9. Configures sessions with MongoDB storage.
10. Initializes Passport.
11. Enables flash messages.
12. Serves static files.
13. Registers the application's routes.
14. Registers a 404 handler.
15. Starts the HTTP server.

The default port is taken from `process.env.PORT`, with `3000` used as the fallback.

# Authentication

Authentication is implemented using **Passport.js**.

The application uses:

- Passport
- Passport Local Strategy
- Express Session
- Connect Mongo
- bcryptjs
- Flash messages

User-related functionality is implemented in `controllers/userController.js`.

The login flow also includes Google reCAPTCHA verification.

Passwords are intended to be stored securely using password hashing rather than plain text.

# Database

The application uses **MongoDB** with **Mongoose**.

The application establishes its database connection through:

```text
config/db.js
```

The primary models include:

```text
models/User.js
models/Blog.js
```

MongoDB is also used to store Express sessions through `connect-mongo`.

---

# Blog System

The blog functionality is handled primarily by:

```text
controllers/blogController.js
models/Blog.js
routes/blog.js
```

The project provides a server-rendered blogging workflow where blog data is retrieved from MongoDB and rendered through EJS templates.

The dashboard routes are separated from the public blog routes, allowing administrative functionality to be kept distinct from the public-facing website.

# Installation

## 1. Clone the repository

```bash
git clone https://github.com/karbarefaal/weblog-project.git
cd weblog-project
```

## 2. Install dependencies

```bash
npm install
```

## 3. Configure environment variables

The application loads environment variables from:

```text
config/config.env
```

Create or configure this file according to your local environment.

Typical configuration will need values for items such as:

```env
NODE_ENV=development
PORT=3000
MONGO_URI=your_mongodb_connection_string
SESSION_SECRET=your_session_secret
```

Additional environment variables may be required for services such as email and reCAPTCHA depending on which parts of the application you use.

> Do not commit secrets, passwords, database credentials, API keys, or private tokens to GitHub.

# Running the Project

## Development

The project provides a development script using Nodemon:

```bash
npm run dev
```

This runs the application with:

```text
NODE_ENV=development
DEBUG=weblog-project
```

and automatically restarts the server when files change.

## Production

Run:

```bash
npm start
```

The production script sets:

```text
NODE_ENV=production
```

and starts the application with Node.js.
